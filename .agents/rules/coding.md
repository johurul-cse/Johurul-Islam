# Fast Coding Rules

1. Inspect before changing.
2. Prefer the simplest working architecture.
3. Build end-to-end MVP before polish.
4. Do not introduce dependencies without a clear benefit.
5. Avoid unnecessary abstraction.
6. Keep components reasonably small.
7. Keep translations centralized.
8. Use browser storage when persistence is needed.
9. Handle loading, empty, success and error states.
10. Verify important user flows in the browser.
11. Do not leave debug code or secrets.
12. Never rewrite working code without a reason.
13. If a feature is difficult and non-essential, defer it.
14. If time is running out, stop feature expansion and stabilize.
